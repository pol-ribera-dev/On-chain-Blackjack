# Blackjack Battle Royale

An on-chain Blackjack-inspired game built in Solidity where players compete for a place in the global Top 3 leaderboard.

The goal is simple: draw cards, get as close as possible to 21 without exceeding it, and secure your position among the best players.

## Game Rules

1. Every player starts with 0 points.
2. Calling `draw()` gives the player a pseudo-random card with a value between 1 and 12.
3. The card value is added to the player's current score.
4. If the player's score exceeds 21, they become busted:
   - They can no longer draw cards.
   - They are removed from the leaderboard if they were present.
5. The three highest scores that do not exceed 21 make up the leaderboard.

## Leaderboard

The contract keeps track of the best three active players.

### Tie-breaking

If two players have the same score, the most recent player takes priority and ranks above previous players with the same score.

### Empty Positions

When a player busts, they are removed from the leaderboard.

To reduce gas costs, empty positions are not immediately filled. They will be occupied naturally when another eligible player interacts with the contract.

## Contract Functions

### `draw()`

Draws a pseudo-random card.

- Can only be called while the player's score is 21 or less
- Increases the player's score
- Updates the leaderboard
- Removes the player from the leaderboard if they bust
- Emits a `RecivedCard` event

### `myScore()`

Returns the caller's current score.

Before returning, the leaderboard is refreshed if necessary.

### `getLeaderboard()`

Returns the complete Top 3 leaderboard as an array of `Player` structs.

I created this function because Solidity's autogenerated getter only returns one array element at a time.

## Randomness

Card values are generated using:

- `uint(keccak256(abi.encodePacked(block.timestamp, msg.sender, block.number)))% 12 + 1`

This project intentionally uses pseudo-randomness for educational purposes.

The generated values are predictable from on-chain information and must not be used in production or in games involving real value.

A production-ready version should use Chainlink VRF or another secure randomness provider.


## Testing

The contract was developed using Remix IDE and tested manually.

The following scenarios were verified:

- Drawing cards
- Score accumulation
- Bust detection
- Leaderboard ordering
- Tie handling
- Player replacement
- Leaderboard cleanup after busting

No automated testing framework (Foundry, Hardhat or Truffle) has been used yet.
